## Critical Bugs

### Bug #1: OpenAI Provider Routing Forced to Demo

**File:** `client/src/lib/council.ts:61`

```typescript
providerOverride: settings?.defaultProvider !== 'demo' ? undefined : 'demo',
```

**Problem:**
- If `defaultProvider === 'demo'` (the default), the override explicitly forces `'demo'`.
- This means even if the user has an OpenAI key and selects OpenAI provider, the council forces demo.
- **Never** allows OpenAI to be actually used.

**Expected:**
- User selects provider.
- System resolves provider based on: (1) explicit selection, (2) available keys, (3) server env.
- Demo only if explicitly selected **or** no keys exist.

---

### Bug #2: Silent Demo Fallback on API Failure

**File:** `client/src/app/api/agent/route.ts:106–113, 142–149`

```typescript
if (!res.ok) {
  console.error('[/api/agent] OpenAI error:', await res.text());
  return NextResponse.json({
    content: getDemoResponse(p.agentId, p.prompt),
    agentId: p.agentId,
    model: 'demo-fallback',
    provider: 'demo',
  });
}
```

**Problem:**
- When OpenAI request fails (invalid key, rate limit, model not available), response returns **demo content**.
- Frontend can't distinguish between real OpenAI response and fallback.
- **No visible error message** — user thinks system works when it doesn't.

**Expected:**
- Return structured error with status, code, and redacted message.
- Frontend shows real error, allows retry, preserves user input.

## Security Review

### Current Risks
1. **API key in headers** — Client sends `x-openai-key` header. If user enters key in browser, it's exposed to network. 🔴 **CRITICAL**
   - Fix: Require server env `OPENAI_API_KEY`. Only allow client key if explicitly typed and marked as "browser-local."
   - Mask key in logs.

2. **Demo response leaks when provider fails** — Silent fallback hides real errors. Could mask compromised key. 🟠 **HIGH**

3. **No rate limiting** — `/api/agent` can be spammed. 🟠 **HIGH**

4. **Secrets not in .gitignore** — Verify `.env` files are never committed.

### Fixes Required
- [ ] Never commit `.env` files.
- [ ] Server env keys only; browser keys only if opt-in and labeled.
- [ ] Mask all logged keys.
- [ ] Add rate limiting middleware.
- [ ] Validate request origins.

## Performance & Reliability

### Current Issues
1. **No error recovery** — If OpenAI fails, user sees demo with no retry button.
2. **No request IDs** — Can't trace issues across frontend/backend.
3. **No caching** — Every request hits OpenAI (no cost reduction).

### Recommendations
- Add request ID to all API responses.
- Implement retry logic with exponential backoff.
- Cache agent responses for identical prompts within 1 hour.
- Add circuit breaker pattern for provider failures.
